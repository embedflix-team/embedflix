An agent that knew which changes could not possibly work — and skipped them.

Embedflix runs the full ML iteration loop on KuaiRand-Pure by itself. Its edge isn’t a bigger model; it’s understanding exactly what the metric rewards, and being able to tell a real gain from noise.

converged validation primary 0.6045  (+0.0029 over the 0.6016 official baseline)  ·  test 0.5975 (+0.0029)  ·  NumPy + LightGBM  ·  0 GPU-hours

Insight — Innovation, 20%Why user-side features cannot move this score

evaluate.py ranks each user’s own ~5 logged impressions. A score term that shifts every one of a user’s impressions by the same amount cannot change their order — it is invisible to GAUC and nDCG@5. Only signal that varies within the list can help.

Integrity — Technical Execution, 35%The “baseline” in the repo wasn’t the baseline

A prior commit titled “restore clean baseline” had silently swapped the shipped log-loss Factorization Machine for an unvalidated loss — its own run-log entry scored primary: None, meaning it never produced a valid score. Every later run measured 0.6039 as “the baseline” and reported a fake +0.0023.

Embedflix restores the official FM from git history, freezes it as a protected reference, and pins it with a reproduction test: validation primary 0.6016 ± 0.0003 over five seeds. It then replaces a noise-accepting 1e-4 accept threshold with a two-stage, seed-confirmed gate, and adds a no-op detector — a bit-identical score means the edit never changed the model, and is logged as such rather than as “technique X failed.”

Model — Technical Execution + InnovationStack the FM into a ranker that optimizes the metric

The plain FM already saturates the item-side signal that IDs alone carry, so instead of adding features to it, the FM’s logit becomes one input feature of a LightGBM lambdarank model that optimizes nDCG@5 directly — alongside train-split-only target encodings of per-video / per-author long_view rate and video engagement ratios. Five-seed rank-averaged to sit below the ε = 0.002 convergence band.

A rejected variant is documented in the source: 4-fold out-of-fold stacking of the FM feature made it worse (0.5905, overfit at iteration 3) — the fold models are weaker than the one used at serving, so the feature’s distribution shifts. Discipline, not luck.

Result — read against the ceiling+0.0029, measured and seed-confirmed

The metrics do not span [0, 1]. A perfect ranker reaches only 0.8645 on the hidden test — 27% of users have no positive label, so their nDCG is 0 for any model. The official baseline already captures ~31% of the attainable range.
